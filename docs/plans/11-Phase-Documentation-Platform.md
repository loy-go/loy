**Phase:** 11  
**Status:** Completed

**Primary Specifications:** [`docs/research/documentation-platform-and-cli-docgen.md`](../research/documentation-platform-and-cli-docgen.md), [`docs/09-CLI-Developer-Experience.md`](../09-CLI-Developer-Experience.md), [`ADR-002`](../adrs/ADR-002-minimal-runtime.md)

## 1. Goal & Objectives

Establish a world-class, zero-JS, publicly deployable documentation platform for Loy:
1. **Zero-JS Static Documentation Platform**: Deploy Astro Starlight in `website/` delivering static HTML/CSS, built-in Pagefind search (zero external SaaS dependency), Expressive Code block highlighting, and client-side Mermaid rendering.
2. **Automated CLI Reference Generator**: Implement `cmd/docgen/main.go` utilizing `github.com/spf13/cobra/doc` to extract documentation directly from Cobra commands in `internal/cli` into typed Starlight pages with frontmatter and semantic route links.
3. **Information Architecture**: Map existing internal specifications (`docs/01-PRD.md` through `docs/22-Traceability-Roadmap.md` and ADRs) into reader-facing categories: Getting Started, Invariants, Tutorials, Architecture Rules Catalog (`ARCH-001` - `ARCH-014`), CLI Reference, Manifest Specification, and ADR Index.
4. **Hermetic Task Runner Integration**: Wire `make docgen` and `make docs-build` to the root `Makefile`.
5. **Continuous Deployment Pipeline**: Add `.github/workflows/docs.yml` to automatically build, test, and deploy documentation to GitHub Pages on merges to main/master.

## 3. Concrete Implementation Steps

### Step 11.1: CLI Reference Generator Engine (`cmd/docgen`)
1. Implement `cmd/docgen/main.go`:
   - Initialize root command via `cli.NewRootCmd()`.
   - Traverse Cobra command tree and build lookup table of command pointers.
   - Prepend Starlight YAML frontmatter (`title`, `description`, `slug`, `sidebar: { order: ... }`).
   - Rewrite markdown links to match Starlight routes (`loy_make_crud.md` -> `/reference/cli/loy-make-crud/`).
   - Strip leading redundant `# <cmd>` heading to prevent duplication with Starlight's automatic `<h1>`.
   - Set `cmd.DisableAutoGenTag = true` to prevent git timestamp noise.
2. Add unit tests in `cmd/docgen/main_test.go` verifying frontmatter generation, slug formatting, and link rewriting.
3. Wire `make docgen` target in root `Makefile`.

### Step 11.2: Astro Starlight Scaffold (`website/`)
1. Initialize `website/` using `pnpm`:
   - Dependencies: `astro`, `@astrojs/starlight`, `astro-mermaid`.
2. Configure `website/astro.config.mjs`:
   - Site title: `Loy Developer Platform`.
   - Social links: GitHub repository.
   - Built-in Pagefind search enabled.
   - Sidebar hierarchy matching the 7 Information Architecture categories.
   - Expressive Code configured with themes, copy button, and line markers.
3. Add `website/tsconfig.json` and scripts in `website/package.json` (`dev`, `build`, `preview`).

### Step 11.3: Generate CLI Command Reference
1. Execute `go run ./cmd/docgen --out website/src/content/docs/reference/cli`.
2. Verify all 20+ commands and subcommands are generated:
   - Root `loy`
   - `loy new`, `loy init`
   - `loy make` (`crud`, `feature`, `model`, `repository`, `service`, `handler`, `job`, `event`, `listener`, `policy`, `test`, `view`, `docker`, `k8s`, `helm`, `ci`)
   - `loy check`
   - `loy dev`
   - `loy doctor`
   - `loy graph`
   - `loy migrate` (`up`, `down`, `status`, `create`, `redo`, `reset`, `version`)
   - `loy version`, `loy completion`
3. Verify frontmatter, sidebar order, and route links.

### Step 11.4: Content Authoring & Specification Migration
1. **Landing Page (`src/content/docs/index.mdx`)**:
   - Hero banner with tagline, action buttons ("Get Started", "View on GitHub").
   - Feature cards highlighting Seams over Components, Zero Runtime, Explicit Wiring, and Architecture Enforcement.
2. **Getting Started (`src/content/docs/start/`)**:
   - `installation.md`: Homebrew, `go install`, precompiled binaries, Docker.
   - `quickstart.md`: 60-second walkthrough from `loy new` to `loy dev`.
   - `prerequisites.md`: Environment validation via `loy doctor`.
3. **Core Concepts (`src/content/docs/concepts/`)**:
   - `architecture.md`: 4-layer unidirectional flow (`Transport -> Application -> Domain <- Infrastructure`).
   - `explicit-wiring.md`: Constructor injection in `internal/app/wiring.go` vs reflection DI.
   - `zero-runtime.md`: Ordinary Go output without framework lock-in.
   - `plan-based-generation.md`: In-memory plan validation and comment region splicing (`// loy:region:...`).
4. **Guides & Tutorials (`src/content/docs/guides/`)**:
   - `vertical-slice.md`: Building a complete feature using `loy make crud`.
   - `database-migrations.md`: Managing migrations with embedded Goose and queries with SQLC.
   - `live-reload.md`: Process supervision with `loy dev`.
   - `deployment.md`: Containerizing with Docker, Kubernetes, and Helm.
5. **Architecture Rules Catalog (`src/content/docs/rules/`)**:
   - Comprehensive reference for `ARCH-001` through `ARCH-014`:
     - Rule ID, title, severity.
     - Architectural rationale.
     - Violating code example.
     - Compliant code remediation.
6. **Manifest & ADRs**:
   - `reference/manifest.md`: Complete annotated `loy.yaml` schema.
   - `adrs/index.md`: Cross-referenced index of all architectural decisions (`ADR-001` - `ADR-017`).

### Step 11.5: Search, Diagramming & Styling Verification
1. Verify Pagefind search index generation during `pnpm build`.
2. Verify Mermaid diagrams render cleanly in both dark and light modes.
3. Verify Expressive Code tabs and diff blocks render properly.

### Step 11.6: CI/CD Deployment Workflow
1. Create `.github/workflows/docs.yml`:
   - Trigger on push to `main`/`master` affecting `website/**`, `cmd/docgen/**`, or `internal/cli/**`.
   - Set up Go 1.24 and pnpm.
   - Run `make docgen` to ensure CLI reference is freshly generated.
   - Run `pnpm build` in `website/` to produce static output with Pagefind index.
   - Deploy to GitHub Pages via `actions/deploy-pages@v4`.
