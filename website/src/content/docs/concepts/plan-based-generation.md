Traditional CLI generators execute immediate filesystem mutations (`os.WriteFile`), leaving projects half-written or corrupt when a generation error occurs halfway through.

Loy enforces **Plan-Based Atomic Generation** ([ADR-007](/adrs/)).

## The Three-Phase Pipeline

```text
Input ──> [ 1. Calculate Plan ] ──> [ 2. Detect Conflicts ] ──> [ 3. Atomic Execution ]
```

### 1. In-Memory Plan Calculation
Generators produce a list of typed `Artifact` models in memory:
- Go source files (`.go`) formatted through `gofmt`.
- SQL migrations and queries.
- Splicing region snippets (`model.MixedOwned`).

### 2. Conflict Detection & Ownership Rules
Before touching the disk, the conflict detector categorizes target files:
- **`DeveloperOwned`**: Files edited by the user. Loy refuses to overwrite unless `--force` is provided.
- **`GeneratedOwned`**: Files carrying the `// Code generated by Loy; DO NOT EDIT.` header. Loy safely regenerates them.
- **`MixedOwned`**: Files like `wiring.go` that mix developer code with generator managed regions (`// loy:region:...`).

### 3. Atomic Execution & Journal Rollback
Loy records every filesystem mutation in an execution journal. If any operation fails (e.g. disk full, permission denied, invalid Go grammar), the executor rolls back all previously executed changes in reverse LIFO order, leaving your git working tree completely clean.
